# Web QA Evidence specification

Create a small useful Python3 standard-library CLI that converts explicit QA observations in JSON into a portable HTML report and CSV case ledger. It does not run browser tests or discover defects; a tester supplies observations. No network calls, dependencies, telemetry, external assets or scripts in generated reports. Actual software is the repository's primary purpose.

`python3 qa_report.py INPUT.json --out OUTPUT_DIR` validates before writing, produces report.html and cases.csv, and exits nonzero with clear errors for invalid input. Required top-level fields: title, build, tested_at, environment (browser, os, viewports array of strings), scope, limitations (array of strings), cases (nonempty array). Each case has id, title, status (pass/fail/blocked/not_run), steps (nonempty array), expected, actual, evidence (array of relative PNG/JPG/JPEG/WebP paths). Fail cases additionally have severity (high/medium/low). IDs unique. String fields nonempty; unknown fields may be ignored. Reports show all cases/status counts, environment/scope, limitations, severity for failures and evidence images. All untrusted text escaped. Reject evidence paths outside input directory, absolute paths, URLs, traversal and symlink escapes; reject missing files and wrong image signatures. Copy safe images under output assets using stable generated names. No reading beyond input directory, no executing inputs. Reject input/output alias and existing nonempty output directory, so source evidence and existing reports cannot be overwritten. CSV cells starting =,+,-,@,tab,CR must be neutralized against spreadsheet formula injection, preserving text otherwise.

Provide an original minimal pickup-quote browser fixture under demo/, with no external services/storage and a persistent visible 'Synthetic QA fixture — no booking or payment is sent' banner. A query parameter `?build=fixed` enables a corrected reference build; default is an explicitly labeled seeded build. Business rules: service Standard C$8, Express C$16, each parcel after the first adds C$2, integer parcel count1–5; valid weight0.1–10kg; SAVE20 gives20% off total for both services; invalid coupon produces inline error; name/email required; form preview preserves inputs on errors; reset clears fields/result. The fixture has exactly two documented intentional defects: seeded Express+SAVE20 fails to discount, and seeded validation error clears parcel count back to1. Fixed build corrects both. Layout usable at390px anddesktop; no artificial layout defect. UI controls have labels and keyboard access. No claim of backend delivery/authentication or production QA.

Include docs/demo-requirements.md documenting expected behavior, seeded defects and fixed build. Include examples/template.json with honest not_run cases, not fictional executed results. No fabricated screenshots, execution timestamps, clients, reviews, sales or tested claims. Root operator will run actual browser cases, save evidence, and author measured sample after the fixture is ready. README leads with useful CLI usage and schema; concise service offer will be added by root only after verification. MIT license with copyright Fristali contributors. Git ignore Python caches and local reports. No CI, paid services, remote publication or changes outside this project.
