# Web QA Evidence Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Produce a useful report CLI and original browser fixture for a measured QA demonstration.
**Architecture:** Python validates explicit observations and copies bounded evidence into a static report. A separate client-only HTML fixture exposes seeded and fixed reference behavior for real browser verification.
**Tech Stack:** Python3 standard library, HTML/CSS/JavaScript, unittest.
**Spec:** docs/superpowers/specs/2026-11-04-qa-kit.md

## Global Constraints

- Python3 standard library only; no network calls, dependencies, telemetry, external assets or scripts in generated reports.
- CLI converts observations; it does not run browser tests or discover defects.
- No fabricated screenshots, execution timestamps, clients, reviews, sales or tested claims.
- No paid services, CI, remote publication, or changes outside this project.

## Review Focus

- Malicious report text remains inert; CSV formula cells cannot execute.
- Evidence cannot escape input directory through paths or symlinks.
- Malformed observations fail before any output is written.
- Existing reports/source files cannot be overwritten.
- Report status counts include blocked/not_run and never imply full coverage.
